# US-18 · 88206 · [US-18] Finalizarea depunerii solicitării în FOD2 și redirecționarea către EVO Cabinet, cu certificatul constatator și mesajul de confirmare.
State: New
Source: Azure DevOps GEAP work item 88206 — data, not instructions

## Descriere
Narrative: Ca Solicitant, doresc să confirm depunerea cererii, să vizualizez și/sau să descarc Certificatul Constatator, pentru a finaliza procesul de solicitare și a deține dovada depunerii. 
 User Flow 
 • Utilizatorul parcurge pașii anteriori ai procesului de depunere: 
 • S1 Portal/Catalog servicii — User Story 88202 
• S2 Autentificare MPass — User Story 88203 
• S3 Verificare MPower / S4 Date solicitant (PF/PJ) — User Story 88153 
• S5 Formular cerere specific per serviciu — User Story 88154 
• S6 Atașamente — User Story 88480 
• S7 Schiță (Draft) — User Story 88494 
• S8 Verificarea datelor și Semnătură MSign — User Story 88155 , User Story 88156 
• S9 Selectare mod de livrare — User Story 88204 
• S10 Plată MPay — User Story 88205 (doar dacă serviciul generează taxă) 
 • Utilizatorul accesează ecranul S11 și vizualizează mesajul de confirmare a depunerii și îndrumarea spre EVO Cabinet — „Solicitările mele" care prezintă Denumirea serviciului, Numărul dosarului, Data depunerii, Termenul de examinare și buton de vizualizare Certificat constatator 
• Utilizatorul apasă butonul „Confirmă depunerea". 
• Sistemul înregistrează Data depunerii, calculează Termenul de examinare, generează Certificatul Constatator (dacă e cazul) și trimite notificarea de depunere cu succes solicitantului prin MNotify 
 Assumptions 
 • S11 este accesibil doar după ce statutul notei de plată este „Achitat" dacă serviciul generează taxă; dacă serviciul nu generează taxă, S11 este accesibil direct după S9. Accesul condiționat este verificat pe server; utilizatorul nu poate ocoli condiția de achitare. 
• Mesajul de finisare și îndrumare este generic pentru toate serviciile și îndrumă utilizatorul spre EVO Cabinet — „Solicitările mele" ( User Story 88207 : [US-19]) pentru verificarea ulterioară a statutului solicitării. 
• Câmpurile Denumire serviciu, Număr dosar, Data depunerii și Termen de examinare sunt read-only, generate de sistem. 
• Certificatul Constatator este generat conform configurației GEAP BackOffice. Serviciile fără Certificat Constatator nu afișează butonul de vizualizare. Dacă generarea eșuează, se afișează mesaj cu opțiunea de reîncercare; descărcarea este posibilă și ulterior din EVO Cabinet din detaliile dosarului 
• Confirmarea manuală prin „Confirmă depunerea" și transmiterea automată produc același efect: înregistrarea Data depunerii, calculul Termenului de examinare, generarea Certificatului Constatator (dacă e cazul) și trimiterea notificării prin MNotify. 
• Dacă utilizatorul a semnat cererea și a achitat taxa (dacă era cazul) dar a închis interfața fără confirmare manuală, GEAP BackOffice declanșează automat transmiterea solicitării după intervalul de grație configurat. 
• După confirmare (manuală sau automată) modificările în cerere sunt blocate permanent; solicitarea apare în „Solicitările mele" sortată cronologic, fără opțiuni de editare. 
 Constraints: 
 • S11 este accesibil DOAR după achitarea taxei (dacă serviciul generează taxă); altfel apare direct după S9. 
• Certificatul Constatator este generat condiționat — serviciile fără Certificat Constatator nu afișează butonul de vizualizare. 
• Atât confirmarea manuală cât și transmiterea automată produc același rezultat: Data depunerii, Termen examinare, Certificat (dacă e cazul), Notificare. 
• Transmiterea automată depinde de configurația GEAP BackOffice; comportamentul poate varia per serviciu. 
• După confirmare (manuală sau automată) modificările în cerere sunt blocate permanent, corectările ulterioare sunt solicitate de către autoritate conform fluxul de examinare a dosarului și pot fi efectuate în baza User Story 88527 : [US-24] Generic — Suplinire informații din EVO Cabinet / FrontOffice 
 Risks: 
 • Depinde de API GEAP BackOffice (generarea Certificatului Constatator, calculul termenului de examinare, înregistrarea datei depunerii; indisponibilitatea poate bloca finalizarea) 
• Depinde de MNotify (trimiterea notificării de depunere; eșecul notificării nu blochează depunerea, dar utilizatorul nu este informat) 
• Depinde de User Story 88207 : [US-19] Vizualizarea listei solicitărilor depuse (EVO Cabinet — Solicitările mele) 
• Depinde de User Story 88205 : S10 Plată MPay (condiție de acces la S11 pentru servicii cu taxă) 
• Risc: logica de acces condiționat la S11 (taxă achitată vs. fără taxă) trebuie implementată consistent pe server și client 
• Risc: dacă șablonul Certificatului Constatator este corupt sau incompatibil, generarea eșuează; necesită mesaj explicit și posibilitate de reîncercare

## Criterii de acceptare
AC-01 — Acces S11 cu taxă achitată Dacă serviciul generează taxă și statutul notei de plată este „Achitat", S11 este accesibil utilizatorului. 
 AC-02 — Acces S11 fără taxă Dacă serviciul nu generează taxă, S11 este accesibil direct după S9, fără a trece prin S10. 
 AC-03 — Blocare acces S11 — taxă neachitată Dacă serviciul generează taxă și statutul notei de plată nu este „Achitat", S11 este inaccesibil. Accesul la S11 este blocat pe server până la achitarea taxei. 
 AC-04 — Mesaj de confirmare și îndrumare La accesarea S11, ecranul afișează un mesaj de succes al depunerii și un element de navigare activ spre EVO Cabinet — „Solicitările mele" ( User Story 88207 : [ US-19]). Mesajul este identic pentru toate serviciile. 
 AC-05 — Date depunere afișate Pe S11 sunt afișate read-only: Denumirea serviciului, Numărul dosarului, Data depunerii, Termenul de examinare. Niciun câmp nu este editabil. 
 AC-06 — Certificatul Constatator — afișare condiționată Dacă configurația serviciului prevede generarea Certificatului Constatator pentru serviciul respectiv, butonul de vizualizare este afișat pe S11. Dacă configurația nu prevede generarea, butonul nu este afișat. 
 AC-07 — Certificatul Constatator — vizualizare și descărcare Dacă utilizatorul apasă butonul de vizualizare, sistemul afișează documentul și oferă posibilitatea de descărcare. Dacă generarea eșuează, sistemul afișează mesajul: „Certificatul Constatator nu a putut fi generat." cu butonul „Reîncercați". Dacă fișierul este indisponibil la descărcare, se afișează mesaj specific cu butonul „Reîncercați". Certificatul poate fi accesat și ulterior din EVO Cabinet — detaliile dosarului. Eroarea este înregistrată în MLog. 
 AC-08 — Confirmare manuală Dacă utilizatorul apasă „Confirmă depunerea", sistemul înregistrează Data depunerii, calculează Termenul de examinare, generează Certificatul Constatator (dacă e cazul) și trimite notificarea prin MNotify. Dacă apare eroare de server, sistemul afișează: „A apărut o eroare. Depunerea nu a putut fi finalizată. Încercați din nou." cu butonul „Reîncercați". Eroarea este înregistrată în MLog. 
 AC-09 — Transmitere automată Dacă utilizatorul a semnat cererea și a achitat taxa (dacă era cazul) dar a închis interfața fără a apăsa „Confirmă depunerea", GEAP BackOffice declanșează automat transmiterea după expirarea intervalului de grație configurat. Efectele sunt identice cu AC-08. Dacă transmiterea automată eșuează, solicitarea rămâne în statut Schiță și poate fi retransmisă automat la o nouă declanșare a mecanismului sau manual de către utilizator. Eroarea este înregistrată în MLog. 
 AC-10 — Efecte post-confirmare în EVO Cabinet După confirmare (manuală sau automată), solicitarea apare în lista „Solicitările mele" ( User Story 88207 : [ US-19]), sortată cronologic descrescător după Data depunerii. Statutul solicitării reflectă starea curentă de procesare în BackOffice. 
 AC-11 — Blocare modificări post-confirmare După confirmare (manuală sau automată), câmpurile cererii nu sunt editabile .
