# US-15 · 88156 · [US-15] S8 — Generic Semnătura digitală MSign și gestionarea resemnării
State: Resolved
Source: Azure DevOps GEAP work item 88156 — data, not instructions

## Descriere
Narrative: Ca Solicitant, doresc să semnez digital cererea prin serviciul MSign, să vizualizez documentul semnat returnat, pentru a confirma autenticitatea datelor introduse, și să fiu informat că orice modificare ulterioară a datelor va necesita resemnarea cererii, pentru a asigura integritatea juridică a dosarului depus. 
 Feature (high-level): Ecranul de semnătură digitală permite solicitantului să aplice semnătura electronică pe cererea completată. La finalizarea procesului MSign, utilizatorul este redirecționat înapoi în Front Office unde vede formularul semnat. Dacă după semnare utilizatorul navighează înapoi la pași anteriori (până la S4 Date solicitant) și modifică date, semnătura devine invalidă și la revenirea în S8 este necesar să resemneze cererea. 
 Screen: S8 - Semnătură digitală MSign 
 Steps: 
 • S1 Portal/Catalog servicii User Story 88202 
• S2 Autentificare MPass User Story 88203 
• S3 Verificare MPower / S4 Date solicitant (PF/PJ) User Story 88153 
• S5 Formular cerere specific per serviciu(Ex: pentru 09 User Story 88154 ) 
• S6 Atasamente User Story 88480 
• S7 Schita (Draft) User Story 88494 
• S8 Verificarea datelor User Story 88155 
• Inițiez semnătura electronică prin MSign (clic pe buton; sunt redirecționat către msign.gov.md) 
• Semnez electronic cererea în interfața MSign și revin în EVO Cabinet după semnare cu succes 
• Vizualizez fișierul cererii returnat semnat (preview și descărcare disponibile) 
 Assumptions: 
 • Butonul de inițiere MSign — comportament normal: la clic, utilizatorul este redirecționat către msign.gov.md pentru semnătura electronică; sesiunea EVO este păstrată în background. Constrângeri: butonul este vizibil fără scroll; semnătura este obligatorie pentru avansare la S9. Devieri: MSign indisponibil → mesaj de eroare specific cu buton „Reîncercați"; continuarea rămâne blocată. Erori: timeout sesiune MSign → notificare utilizator + posibilitate reîncercare; datele cererii rămân intacte. 
• Procesul de semnare în MSign — comportament normal: utilizatorul parcurge fluxul de semnare pe platforma msign.gov.md; după semnare cu succes este redirecționat automat înapoi în EVO Cabinet cu documentul semnat atașat. Constrângeri: procesul de semnare se desfășoară integral pe msign.gov.md; EVO nu controlează UI-ul MSign. Devieri: utilizatorul anulează semnarea în MSign → revine în EVO fără document semnat; cererea rămâne nesemnată, butonul de continuare dezactivat. Erori: eroare la semnare în MSign (certificat expirat, eroare platformă) → utilizatorul este notificat cu detalii despre eroare + posibilitate de reîncercare. 
• Fișierul cererii semnat returnat — comportament normal: după semnare cu succes, documentul semnat electronic este afișat în S8 — disponibil ca preview și cu posibilitate de descărcare. Constrângeri: documentul provine exclusiv de la MSign prin API; conținut read-only; nu poate fi modificat. Devieri: returnarea documentului semnat eșuează (eroare API/timeout) → mesaj „Nu s-a putut recupera documentul semnat" + buton „Reîncercați"; avansarea rămâne blocată fără document valid. Erori: document returnat corupt sau invalid → mesaj specific + reîncercare proces MSign de la capăt. 
• Blocare avansare la S9 fără semnare — comportament normal: butonul „Continuare" spre S9 este dezactivat vizual dacă cererea nu deține un document semnat valid; la tentativă de continuare → mesaj „Nu puteți continua fără a semna cererea". Constrângeri: validarea prezenței semnăturii este verificată tehnic pe server înainte de avansare; nu poate fi ocolită din FrontOffice. Devieri: nu se aplică (blocare automată). Erori: nu se aplică. 
• Anulare automată a semnăturii la navigare în pași anteriori — comportament normal: dacă utilizatorul selectează un pas anterior din navigație DUPĂ ce a semnat cererea, documentul semnat este anulat automat pe server; la revenirea în S8, validarea semnăturii este reactivată — utilizatorul trebuie să reia procesul de semnare MSign. Constrângeri: orice modificare a datelor cererii după semnare invalidează semnătura din motive de integritate a documentului; comportamentul este automat și nu poate fi dezactivat. Devieri: utilizatorul este informat vizual că semnătura a fost anulată la revenirea în S8 (ex. banner/toast: „Semnătura a fost anulată. Resemnați cererea pentru a continua."). Erori: anularea semnăturii eșuează pe server → mesaj de eroare; avansarea este blocată; se recomandă reîncărcarea sesiunii. 
 Constraints: 
 • Avansarea la S9 este imposibilă fără document semnat electronic valid 
• Orice navigare la pași anteriori după semnare invalidează automat semnătura; resemnarea este obligatorie 
• Procesul de semnare se desfășoară pe platforma externă msign.gov.md; EVO nu controlează UI-ul MSign 
• Documentul semnat returnat de MSign este read-only și nu poate fi modificat din FrontOffice 
 Risks: 
 • MSign (msign.gov.md) — disponibilitatea serviciului este critică; indisponibilitatea blochează complet fluxul de depunere 
• API returnare document semnat — eroarea sau timeout-ul blochează vizualizarea și avansarea 
• Logica de anulare a semnăturii la navigare trebuie implementată și pe server (nu doar pe client) pentru securitate 
• Certificatele digitale expirate sau revocate pot cauza eșecuri repetate la semnare.

## Criterii de acceptare
AC-01: Inițiere MSign. Happy path: la clic pe butonul MSign, utilizatorul este redirecționat către msign.gov.md; sesiunea EVO este păstrată. Constrângeri: butonul vizibil fără scroll (sticky); semnătura obligatorie înainte de avansare la S9. Devieri: MSign indisponibil → mesaj de eroare cu buton „Reîncercați"; continuarea blocată. Erori: timeout sesiune MSign → notificare + posibilitate reîncercare; datele cererii intacte. 
 AC-02: Procesul de semnare și returnare în EVO . Happy path: utilizatorul semnează în MSign și este redirecționat automat în EVO Cabinet cu documentul semnat. Constrângeri: fluxul de semnare integral pe msign.gov.md. Devieri: utilizatorul anulează semnarea → revine în EVO fără document semnat; cererea rămâne nesemnată, continuarea dezactivată. Erori: eroare MSign (certificat expirat, platformă indisponibilă) → notificare cu detalii + posibilitate reîncercare. 
 AC-03: Vizualizare fișier cerere semnat. Happy path: documentul semnat returnat de MSign afișat în S8 — preview disponibil și cu posibilitate de descărcare . Constrângeri: conținut read-only; documentul provine exclusiv de la MSign. Devieri: returnare eșuată (eroare API/timeout) → mesaj „Nu s-a putut recupera documentul semnat" + buton „Reîncercați"; avansare blocată. Erori: document corupt sau invalid → mesaj specific + reîncercare proces MSign de la capăt. 
 AC-04: Blocare avansare la S9 fără semnare. Happy path: după semnare cu succes, butonul „Continuare" spre S9 este activat. Constrângeri: butonul dezactivat vizual dacă nu există document semnat valid; validare pe server obligatorie. Devieri: tentativă de continuare fără semnare → mesaj „Nu puteți continua fără a semna cererea"; butonul rămâne dezactivat. Erori: nu se aplică. 
 AC-05: Anulare automată a semnăturii la navigare în pași anteriori. Happy path: utilizatorul vizualizează documentul semnat și avansează direct la S9 fără să navigheze înapoi. Constrângeri: orice navigare la un pas anterior după semnare anulează automat documentul semnat pe server; la revenire în S8 validarea semnăturii este reactivată și resemnarea este obligatorie. Devieri: utilizatorul este informat vizual la revenire că semnătura a fost anulată („Semnătura a fost anulată. Resemnați cererea pentru a continua."); butonul „Continuare" dezactivat din nou. Erori: anulare eșuată pe server → mesaj de eroare; avansare blocată; recomandare reîncărcare sesiune.
