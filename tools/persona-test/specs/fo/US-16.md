# US-16 · 88204 · [US-16] S9 — Generic  Selectare mod de livrare a actului permisiv
State: Resolved
Source: Azure DevOps GEAP work item 88204 — data, not instructions

## Descriere
Narrative: Ca Solicitant, doresc să selectez modul preferat de livrare a actului permisiv (pe hârtie la instituția emitentă sau prin MDelivery), pentru a primi documentul în forma și la locul convenabil mie. 
 Screen: S9 — Selectare mod de livrare a actului permisiv 
 Steps: 
 • S1 Portal/Catalog servicii User Story 88202 
• S2 Autentificare MPass User Story 88203 
• S3 Verificare MPower / S4 Date solicitant (PF/PJ) User Story 88153 
• S5 Formular cerere specific per serviciu (Ex: pentru 09 User Story 88154 ) 
• S6 Atasamente User Story 88480 
• S7 Schita (Draft) User Story 88494 
• S8 Verificarea datelor și Semnatura MSign User Story 88155 User Story 88156 
• Vizualizez opțiunile de livrare disponibile — afișate conform configurației din pașaportul serviciului GEAP BackOffice/RSSPA 
• Selectez tipul de livrare din opțiunile disponibile — utilizatorul alege din 3 variante posibile (afișate condiționat per pașaport): „Livrare EVO Cabinet" (implicit), „Pe hârtie la instituția emitentă", „Pe hârtie prin MDelivery" 
• Completez adresa de livrare (doar dacă a fost selectat „Pe hârtie prin MDelivery"): Raion, Localitate, Stradă, Număr, Bloc, Apartament/oficiu, Cod poștal 
 Assumptions: 
 • Afișarea secțiunii de selecție a livrării — comportament normal: secțiunea se afișează cu opțiunile configurate în pașaportul serviciului GEAP BackOffice/RSSPA. Constrângeri: tipurile disponibile sunt definite exclusiv în pașaport; FrontOffice nu poate adăuga sau elimina tipuri. Devieri: (1) dacă pașaportul conține DOAR „Livrare EVO Cabinet" — secțiunea de selecție nu se afișează; tipul este aplicat automat și utilizatorul avansează direct; (2) dacă pașaportul conține un singur tip de livrare pe hârtie — tipul este precompletat automat în solicitare fără interacțiune din partea utilizatorului; (3) dacă pașaportul conține multiple tipuri — utilizatorul poate selecta dintre opțiunile disponibile. Erori: API pașaport GEAP BackOffice/RSSPA indisponibil → mesaj de eroare cu buton „Reîncercați"; avansarea este blocată până la recuperarea configurației. 
• „Livrare EVO Cabinet" (implicit) — comportament normal: selectată implicit indiferent dacă pașaportul include alte opțiuni, sau dacă e indicat doar Electronic; nu necesită câmpuri suplimentare; actul emis va fi disponibil în EVO Cabinet al solicitantului. Constrângeri: fără date suplimentare de completat. Erori: nu se aplică (opțiune fără câmpuri de input). 
• „Pe hârtie la instituția emitentă" — comportament normal: la selectare nu apar câmpuri suplimentare; actul va fi ridicat fizic de la instituția emitentă. Constrângeri: disponibil doar dacă configurat în pașaportul serviciului. Devieri: dacă este singurul tip de livrare pe hârtie configurat → precompletat automat fără interacțiune utilizator. Erori: nu se aplică (opțiune fără câmpuri de input). 
• „Pe hârtie prin MDelivery" — comportament normal: la selectare se afișează dinamic câmpurile de adresă de livrare: Raion, Localitate, Cod poștal (obligatorii), Stradă, Număr, Bloc, Apartament/oficiu (opționale). Raion și Localitate — selectate din nomenclatorul CUATM; câmpurile se ascund complet dacă utilizatorul schimbă tipul de livrare. Constrângeri: Raion, Localitate, Cod poștal sunt câmpuri obligatorii; Stradă, Număr, Bloc, Apartament/oficiu sunt opționale. Devieri: dacă este singurul tip de livrare pe hârtie configurat → precompletat automat; câmpurile de adresă sunt activate imediat. Erori: API CUATM indisponibil → Raion/Localitate afișează eroare cu buton „Reîncercați"; câmpurile obligatorii goale la tentativa de avansare → mesaj inline per câmp; Cod poștal format invalid → mesaj inline cu formatul așteptat. Exemplu de completare MD-0000. 
• Precompletare automată (un singur tip pe hârtie în pașaport) — comportament normal: dacă pașaportul conține un singur tip de livrare pe hârtie, acesta este precompletat automat în solicitare; utilizatorul vede tipul selectat fără a fi nevoit să aleagă. Constrângeri: precompletarea este automată conform configurației; utilizatorul poate modifica dacă alte tipuri sunt disponibile. Devieri: dacă tipul precompletat este „Pe hârtie prin MDelivery" — câmpurile de adresă sunt activate imediat și trebuie completate. Erori: nu se aplică (logică de precompletare din configurare). 
 Constraints: 
 • Tipurile de livrare disponibile sunt definite exclusiv în pașaportul serviciului GEAP BackOffice/RSSPA; nu pot fi modificate din FrontOffice 
• Dacă pașaportul conține doar „Livrare EVO Cabinet" — secțiunea S9 nu se afișează; livrarea este aplicată automat în EVO Cabinet. 
• Dacă pașaportul conține un singur tip pe hârtie — tipul este precompletat automat fără interacțiune utilizator 
• Câmpurile de adresă MDelivery (Raion, Localitate, Cod poștal ) sunt obligatorii; Stradă, Număr, Bloc, Apartament/oficiu - sunt opționale 
• Raion și Localitate sunt selectate din nomenclatorul CUATM (nu input liber) 
 Risks: 
 • API GEAP BackOffice/RSSPA — configurația tipurilor de livrare din pașaport; indisponibilitatea blochează afișarea S9 
• API CUATM — nomenclatorul Raion/Localitate pentru adresa MDelivery; indisponibilitatea blochează completarea adresei 
• MDelivery (mdelivery.gov.md) — integrarea cu serviciul de livrare poștală; adresa introdusă va fi transmisă MDelivery la emiterea actului

## Criterii de acceptare
AC-01: Afișarea secțiunii S9 conform configurației pașaportului. Happy path: secțiunea afișează opțiunile de livrare configurate în pașaportul serviciului GEAP BackOffice/RSSPA; implicit selectat „Livrare EVO Cabinet". Constrângeri: opțiunile provin exclusiv din pașaport. Devieri: (1) pașaport = doar „Livrare EVO Cabinet" → secțiunea S9 nu se afișează; livrare aplicată automat; (2) pașaport = un singur tip pe hârtie → tipul precompletat automat fără interacțiune utilizator; (3) pașaport = multiple tipuri → utilizatorul poate alege. Erori: API pașaport indisponibil → mesaj de eroare cu buton „Reîncercați"; avansare blocată. 
 AC-02: „Livrare EVO Cabinet" (implicit) . Happy path: opțiune implicită, fără indicare în pașaportul serviciului; fără câmpuri suplimentare; actul disponibil în EVO Cabinet după emitere. Constrângeri: nu necesită date suplimentare. Devieri: pașaport fără EVO Cabinet → opțiunea nu se afișează. Erori: nu se aplică. 
 AC-03: „Pe hârtie la instituția emitentă" . Happy path: la selectare nu apar câmpuri suplimentare; actul va fi ridicat fizic de la instituția emitentă. Constrângeri: disponibil doar dacă configurat în pașaport. Devieri: singurul tip pe hârtie configurat → precompletat automat. Erori: nu se aplică. 
 AC-04: „Pe hârtie prin MDelivery" — selecție și câmpuri de adresă. Happy path: la selectare se afișează dinamic câmpurile de adresă de livrare; Raion și Localitate selectate din nomenclatorul CUATM; la schimbarea tipului câmpurile se ascund. Constrângeri: Raion, Localitate , Cod poștal — obligatorii; Stradă, Număr, Bloc, Apartament/oficiu — opționale. Devieri: singurul tip pe hârtie → precompletat automat; câmpurile de adresă activate imediat. Erori: câmpuri obligatorii goale la avansare → mesaj inline per câmp; API CUATM indisponibil → eroare dropdown Raion/Localitate cu buton „Reîncercați"; Cod poștal format invalid → mesaj inline cu formatul așteptat. 
 AC-05: Precompletare automată pentru un singur tip de livrare pe hârtie. Happy path: dacă pașaportul conține un singur tip de livrare pe hârtie, acesta este precompletat automat; utilizatorul vede tipul selectat fără interacțiune. Constrângeri: precompletarea automată conform configurației pașaportului. Devieri: tip precompletat = „Pe hârtie prin MDelivery" → câmpurile de adresă activate imediat și obligatorii. Erori: nu se aplică.
