# US-13 · 88154 · [US-13] S5 Completarea formularului de cerere 09
State: Ready for Deployment
Source: Azure DevOps GEAP work item 88154 — data, not instructions

## Descriere
Narrative: Ca Solicitant identificat, doresc să completez formularul cererii Autorizației sanitare de funcționare cu datele obiectului (denumire, adresă, contact), să selectez subdiviziunea de procesare, codurile CAEM cu subgenurile de activitate și persoana de contact, pentru a înregistra corect cererea și a o direcționa spre subdiviziunea competentă. 
 Lista servicii RSSPA ID -> 008002372
 Screens: S5 — Formular cerere; 
 Steps: 
 • S1 Portal/Catalog servicii User Story 88202 
• S2 Autentificare MPass User Story 88203 
• S3 Verificare MPower / S4 Date solicitant (PF/PJ) User Story 88153 
 Service Specific details 
 • Indic „Obiectul autorizat" — câmp text liber, obligatoriu. 
• Indic „Adresa obiectului": Raionul și localitatea — obligatorii; strada, nr., bloc, apartament/oficiu — opționale. Mesaj de atenționare permanent: „Introduceți adresa exactă a obiectului". 
• Indic „Telefonul" și „Adresa de email" ale obiectului — ambele obligatorii, validate după format. Pentru îndrumare solicitant: +37300000000. Mesaj validare format camp telefon: „Se va indica număr telefon mobil +37300000000 sau fix +373(cod regiune)000000." 
• Selectez „Procesat de subdiviziunea" din lista subdiviziunilor de procesare — obligatoriu. Precompletat dacă serviciul are o singură subdiviziune sau dacă subdiviziunea corespunzătoare regiunii adresei obiectului poate fi determinată automat. 
• Selectez cod(uri) CAEM din lista disponibilă a serviciului. Pentru mai multe coduri într-o solicitare, adaug fiecare cod prin butonul „Adaugă". 
• Per fiecare cod CAEM selectat, bifez subgenurile de activitate necesare din lista afișată dinamic. 
• Selectez persoana de contact — utilizatorul alege din 2 opțiuni: 
 • (A) „Eu sunt persoana de contact" — selectat implicit, autocompletat cu Nume, Prenume, Telefon din datele persoanei fizice/reprezentantului, read-only; 
• (B) „Altă persoană de contact" — câmpuri editabile Nume, Prenume, Telefon cu exemple de completare, toate obligatorii. 
 Assumptions: 
 • Obiectul autorizat — câmp text liber, cu element de îndrumare „i": la hover/atingere se afișează textul „Specificați tipul exact al obiectului supus autorizării (denumirea trebuie să reflecte profilul real de activitate). Exemple de completare în funcție de domeniu: Frizerie, Salon de frumusețe; Instituție de educație timpurie (grădiniță), Liceu, Gimnaziu, Școală primară; Cabinet medical, Clinică medicală/stomatologică, Centru medical de diagnostic, Laborator medical, Spital; Apeduct, Sondă arteziană, Turn de apă." Happy path: utilizatorul tastează denumirea; câmpul acceptă orice text. Constrângeri: câmp obligatoriu; salvarea/continuarea blocată dacă gol. Devieri: N/A. Erori: câmp gol la tentativa de salvare → eroare inline „Câmpul este obligatoriu". 
• Adresa obiectului — structură câmpuri: Raionul și localitatea sunt selectate din nomenclatorul CUATM (liste predefinite), ambele obligatorii. Strada (nomenclator), nr., bloc, apartament/oficiu(câmpuri text) sunt câmpuri opționale. Mesajul de atenționare „Introduceți adresa exactă a obiectului" este afișat permanent în secțiunea adresei, nu ca eroare. Constrângeri: continuarea blocată dacă raionul sau localitatea lipsesc. Devieri: câmpurile opționale pot rămâne goale. Erori: tentativa de continuare cu raion/localitate goale → eroare inline pe câmpurile respective. 
• Telefon obiect — validare și îndrumare: Happy path: utilizatorul introduce numărul; câmpul acceptă format mobil (+37300000000) sau fix (+373(cod regiune)000000). Exemplu de completare: +37300000000 afișat în câmpul gol ca îndrumare. Constrângeri: câmp obligatoriu; format validat. Devieri: N/A. Erori: format invalid → eroare inline „Se va indica număr telefon mobil +37300000000 sau fix +373(cod regiune)000000"; câmpul gol la salvare → eroare inline „Câmpul este obligatoriu". 
• Email obiect — validare: Happy path: utilizatorul introduce adresa email validă. Constrângeri: câmp obligatoriu; validat după format RFC (text@domeniu.tld). Devieri: N/A. Erori: format invalid → eroare inline „Adresa email nu este validă"; câmp gol → „Câmpul este obligatoriu". 
• Subdiviziunea de procesare — logica precompletare: Happy path (1 subdiviziune): câmpul este precompletat automat cu unica subdiviziune a serviciului. Happy path (mai multe subdiviziuni, adresă introdusă): sistemul determină subdiviziunea competentă pe baza raionului/municipiului introdus la adresa obiectului și precompletează câmpul; utilizatorul poate modifica selecția. Edge case (mai multe subdiviziuni, regiune nedeterminabilă din adresă sau adresă neintrodusă încă): lista subdiviziunilor este afișată pentru selecție manuală. Constrângeri: câmp obligatoriu; precompletarea bazată pe adresă se face doar dacă raionul/municipiul a fost deja selectat. Erori: tentativa de salvare fără subdiviziune selectată → eroare inline „Câmpul este obligatoriu". 
• CAEM — sursă și filtrare: Lista codurilor CAEM active este filtrată după pașaportul serviciului din GEAP BackOffice și activitățile agentului economic/persoanei patentate din RSUD. Mesaj informativ permanent: „Codurile CAEM se prezintă în dependență de activitățile înregistrate în RSUD." Se afișează ultimul nivel ierarhic. Edge case — listă goală: mesaj specific + continuare blocată. Edge case — RSUD indisponibil: eroare cu buton „Reîncercați"; date formular păstrate. 
• CAEM — restricție secțiune: Primul cod selectat setează secțiunea activă; codurile din alte secțiuni sunt dezactivate automat. Mesaj de îndrumare permanent: „Într-o solicitare pot fi selectate doar coduri ale unei secțiuni. Ex: dacă selectați coduri secțiunii Q, se pot adăuga alte coduri CAEM doar ale secțiunii Q." Tentativa de selecție din altă secțiune → element dezactivat. 
• CAEM — adăugare multiplă și duplicate: Butonul „Adaugă" permite înregistrarea de coduri suplimentare. Duplicat detectat → mesaj avertizare: „Dvstră ați înregistrat deja acest cod CAEM"; codul nu este adăugat. Minim 1 / maxim toate codurile permise ale secțiunii. 
• Subgenuri — filtrare dinamică: La selectarea unui cod CAEM, subgenurile active sunt afișate dinamic (clasificator intern GEAP). Minim 1 subgen per cod CAEM selectat. Edge case — cod fără subgenuri active: codul dezactivat în listă sau mesaj „Niciun subgen disponibil pentru acest cod CAEM". 
• Persoana de contact — opțiunea A (implicit): „Eu sunt persoana de contact" selectat implicit; Nume, Prenume, Telefon autocompletate din datele persoanei fizice/reprezentantului (S3), read-only. Edge case — date incomplete din S3: câmpurile disponibile pre-populate, cele lipsă afișate goale read-only. 
• Persoana de contact — opțiunea B: „Altă persoană de contact" → câmpuri editabile Nume, Prenume, Telefon cu exemplu de completare per câmp. Toate câmpurile obligatorii; validare format telefon conform acelorași reguli ca la telefonul obiectului. 
 Constraints: 
 • Precompletarea subdiviziunii din adresă funcționează doar dacă raionul/municipiul a fost selectat și dacă a fost inregistrată corecta adresa subdiviziunii în MPass; nu se bazează pe câmpurile opționale (stradă, nr.). 
• Configurația CAEM activă per serviciu și maparea subdiviziunilor pe regiuni sunt gestionate în GEAP BackOffice; FrontOffice consumă prin API. 
• Subgenurile de activitate sunt clasificator intern GEAP; nu provin din nomenclatoare externe. 
 Risks: 
 • Indisponibilitatea RSUD poate bloca afișarea listei CAEM sau returna activități incomplete. 
• Maparea raion → subdiviziune poate fi incorectă dacă configurația din BackOffice nu acoperă toate unitățile administrativ-teritoriale. 
• Lipsa activităților RSUD la agenții economici blochează depunerea cererii

## Criterii de acceptare
• AC-01 — Obiectul autorizat. Câmpul afișează elementul de îndrumare „i"; la hover/atingere se afișează textul de îndrumare cu tipurile de obiecte și exemplele de completare. Happy path: utilizatorul completează câmpul text; valoarea este acceptată. Constrângeri: obligatoriu. Devieri: N/A. Erori: câmp gol la salvare → eroare inline „Câmpul este obligatoriu"; continuare blocată. 
• AC-02 — Adresa obiectului — câmpuri obligatorii. Happy path: raionul și localitatea selectate din nomenclator CUATM; continuarea activă. Constrângeri: raion + localitate obligatorii; strada/nr/bloc/ap/oficiu opționale. Mesaj de atenționare ”Introduceți adresa exactă a obiectului” afișat permanent. Devieri: câmpurile opționale pot rămâne goale. Erori: raion sau localitate goale la salvare → eroare inline per câmp; continuare blocată. 
• AC-03 — Telefon obiect. Happy path: utilizatorul introduce număr valid (mobil sau fix MD); câmpul acceptat. Exemplu de completare +37300000000 afișat în câmpul gol. Constrângeri: obligatoriu; format: mobil +37300000000 sau fix +373(cod regiune)000000. Devieri: N/A. Erori: format invalid → eroare inline „Se va indica număr telefon mobil +37300000000 sau fix +373(cod regiune)000000"; câmp gol → „Câmpul este obligatoriu". 
• AC-04 — Email obiect. Happy path: email valid introdus; câmpul acceptat. Constrângeri: obligatoriu; format RFC. Devieri: N/A. Erori: format invalid → eroare inline „Adresa email nu este validă"; câmp gol → „Câmpul este obligatoriu". 
• AC-05 — Subdiviziunea — precompletare 1 subdiviziune. Happy path: serviciul are o singură subdiviziune → câmpul precompletat automat și afișat read-only. Constrângeri: obligatoriu; utilizatorul nu poate modifica. Devieri: N/A. Erori: N/A. 
• AC-06 — Subdiviziunea — precompletare din adresă (mai multe subdiviziuni). Happy path: raionul/municipiul obiectului selectat → sistemul determină subdiviziunea competentă și precompletează câmpul; utilizatorul poate modifica selecția. Constrângeri: precompletarea se activează doar după selectarea raionului/municipiului. Devieri: regiune nedeterminabilă sau adresă neintrodusă → câmpul afișat gol pentru selecție manuală din listă. Modificarea adresei după precompletare resetează automat subdiviziunea. Erori: tentativa de salvare fără subdiviziune → eroare inline „Câmpul este obligatoriu". 
• AC-07 — CAEM filtrare și afișare. Happy path: lista afișează codurile de ultimele nivel ierarhic active din BackOffice, filtrate cu activitățile RSUD; mesaj informativ RSUD afișat permanent. Constrângeri: doar coduri active și la ultimul nivel ierarhic. Devieri: listă goală → mesaj specific + blocat. Erori: RSUD indisponibil → eroare cu buton „Reîncercați"; date păstrate. 
• AC-08 — CAEM restricție secțiune. Happy path: primul cod selectat setează secțiunea activă; celelalte dezactivate automat; mesaj de îndrumare permanent. Constrângeri: o singură secțiune per cerere. Devieri: tentativa de selecție din altă secțiune → element dezactivat. Erori: N/A. 
• AC-09 — CAEM duplicate și obligativitate. Happy path: coduri unice adăugate prin „Adaugă"; min 1 / max toate codurile secțiunii. Constrângeri: duplicat → mesaj „Dvstră ați înregistrat deja acest cod CAEM", neadăugat. Erori: 0 coduri la salvare → eroare inline „Selectați cel puțin un cod CAEM"; blocat. 
• AC-10 — Subgenuri filtrare și obligativitate. Happy path: subgenuri active afișate dinamic per CAEM; min 1 bifat per cod. Constrângeri: clasificator intern GEAP. Devieri: cod fără subgenuri → dezactivat sau mesaj „Niciun subgen disponibil". Erori: cod CAEM fără subgen bifat la salvare → eroare inline „Selectați cel puțin un subgen pentru [cod CAEM]"; blocat. 
• AC-11 — Persoana de contact opțiunea A (implicit). Happy path: „Eu sunt persoana de contact" selectat implicit; Nume, Prenume, Telefon autocompletate din S3, read-only. Devieri: date incomplete din S3 → câmpurile disponibile pre-populate, cele lipsă goale read-only. Erori: N/A. 
• AC-12 — Persoana de contact opțiunea B. Happy path: „Altă persoană de contact" → câmpuri editabile cu exemplu de completare; utilizatorul completează; toate obligatorii. Constrângeri: Telefon validat conform acelorași reguli ca AC-03. Erori: câmp gol sau format invalid la salvare → eroare inline per câmp; blocat.
