# US-14 · 88155 · [US-14] S8 — Verificarea datelor cererii inainte de semnare
State: Resolved
Source: Azure DevOps GEAP work item 88155 — data, not instructions

## Descriere
Narrative: Ca Solicitant, doresc să verific toate datele înregistrate înainte de semnare, pentru a mă asigura că cererea este corectă și completă înainte de depunere, și sa pot reveni la pașii anteriori pentru a completa sau corecta informațiile lipsa. 
 Feature (high-level): Ecranul de verificare prezintă un sumar complet al cererii in format de tipar (preview PDF-like) - toate datele completate de solicitant, datele precompletate din MConnect, atașamentele încărcate și informațiile serviciului. Solicitantul poate revizui fiecare secțiune si, daca identifica lipsuri sau erori, poate naviga inapoi pana la S4 Date solicitant pentru a efectua corecții. Navigarea inapoi păstrează toate datele introduse anterior fara pierderi. 
 Screen: S7 - Verificare date cerere 
 Steps: 
 • S1 Portal/Catalog servicii User Story 88202 
• S2 Autentificare MPass User Story 88203 
• S3 Verificare MPower / S4 Date solicitant (PF/PJ) User Story 88153 
• S5 Formular cerere specific per serviciu(Ex: pentru 09 User Story 88154 ) 
• S6 Atasamente User Story 88480 
• S7 Schita (Draft) User Story 88494 
• Vizualizez toate datele cererii în format read-only, structurate pe secțiuni: Date generale ale solicitării, Date despre solicitant, Date despre cerere, Atașamente 
• Selectez un pas anterior din navigație pentru a corecta datele și revin la verificare după corectare 
• Vizualizez formularul de tipar al cererii cu toate datele înregistrate 
• Inițiez semnătura electronică MSign (buton vizibil fără scroll) 
 Assumptions: 
 • Număr dosar — comportament normal: generat automat la intrarea în S5 conform regulilor predefinite din GEAP BackOffice; afișat read-only. Constrângeri: formatul este configurat în BackOffice; nu poate fi modificat din FrontOffice. Devieri: dacă generarea eșuează sau regula nu este configurată, câmpul afișează „—" cu avertisment vizual. Erori: API BackOffice indisponibil → mesaj de eroare cu buton „Reîncercați"; restul datelor rămân vizibile. 
• Autoritatea emitentă — comportament normal: precompletată din pașaportul serviciului (RSSPA); afișată read-only. Constrângeri: valoarea provine din configurația serviciului; nu este editabilă. Devieri: dacă lipsește din pașaportul serviciului, afișează „Nedefinit" + avertisment informativ. Erori: nu se aplică (câmp static preîncărcat). 
• Subdiviziunea de procesare — comportament normal: precompletată dacă a fost selectată sau auto-selectată în S4; afișată read-only. Constrângeri: valoarea reflectă selecția din S4. Devieri: serviciu fără subdiviziuni configurate sau subdiviziune neselectată → afișează „Nedefinit". Erori: nu se aplică (câmp static). 
• Tipul solicitării — comportament normal: precompletat în funcție de locul de inițiere a dosarului; afișat read-only. Logică de completare: (1) dacă dosarul a fost inițiat din „Servicii disponibile" → tipul = „Eliberare"; (2) dacă dosarul a fost inițiat din „Actele permisive emise ale solicitantului" → tipul = tipul de postproces selectat la inițiere (Reperfectare / Prelungire / Eliberare Duplicat / Suspendare / Reluarea valabilității / Retragere / Anulare). Constrângeri: câmpul este read-only; tipul nu poate fi schimbat din S5. Devieri: dacă tipul nu a putut fi determinat, afișează „Nedefinit" + avertisment. Erori: nu se aplică (câmp static). 
• Date despre solicitant — câmpuri universale (Tipul solicitantului, IDNP, Nume, Prenume, Telefon, Email) — comportament normal: afișate read-only pentru toți solicitanții, preluate din autentificarea MPass. Devieri: câmpuri opționale necompletate afișează „—". Erori: nu se aplică (read-only). 
• Date despre solicitant — câmpuri persoană juridică (IDNO, Denumire companie, Telefon companie, Email companie) — comportament normal: afișate read-only DOAR dacă tipul solicitantului este Persoană juridică; ascunse complet pentru persoană fizică. Devieri: câmpuri opționale necompletate afișează „—". Erori: nu se aplică (read-only). 
• Denumire obiect — comportament normal: afișată read-only valoarea introdusă în S4. Devieri: câmp obligatoriu — dacă nu a fost completat, accesul la S5 este blocat din S4. Erori: nu se aplică (read-only). 
• Adresa unității economice (Raion/Municipiu, Oraș/Comună, Sector, Stradă, Nr. casei, Bloc, Apartament/oficiu, Cod poștal, Telefon, Email) — comportament normal: toate subcomponentele afișate read-only conform valorilor din S4. Constrângeri: câmpurile obligatorii validate la S4; accesul la S5 este blocat dacă lipsesc. Devieri: câmpuri opționale necompletate (Bloc, Apartament/oficiu, Cod poștal) afișează „—". Erori: nu se aplică (read-only). 
• Persoana de contact (Nume, Prenume, Telefon) — comportament normal: afișată read-only; dacă solicitantul este el însuși persoana de contact, datele sunt preluate din autentificarea MPass. Devieri: câmpuri opționale necompletate afișează „—". Erori: nu se aplică (read-only). 
• Activități CAEM cu subgenuri — comportament normal: lista codurilor CAEM selectate afișată sortată A-Z; per fiecare cod sunt listate subgenurile bifate; totul read-only. Constrângeri: sortare obligatorie A-Z; subgenuri grupate per cod CAEM. Erori: nu se aplică (read-only). 
• Atașamente — documente predefinite — comportament normal: lista documentelor predefinite din RSSPA afișată cu Denumire și status Atașat (DA/NU); read-only; Devieri: dacă lista predefinită este goală, secțiunea nu se afișează. Erori: nu se aplică (read-only). 
• Atașamente — documente suplimentare — comportament normal: secțiunea se afișează DOAR dacă solicitantul a atașat cel puțin un document suplimentar; afișată cu Denumire și status Atașat (DA/NU); read-only. Devieri: dacă nu există documente suplimentare atașate, secțiunea nu se afișează (nu este un câmp gol, ci secțiunea este complet omisă). Erori: nu se aplică (read-only). 
• Navigare la pas anterior și corectare — comportament normal: solicitantul selectează orice pas completat anterior din stepper; câmpurile editabile devin disponibile; la revenire în S8 datele modificate sunt reflectate. Constrângeri: câmpurile read-only din pași anteriori nu pot fi modificate; revenire la S8 posibilă DOAR dacă toate câmpurile obligatorii din pașii intermediari sunt completate. Devieri: câmpuri obligatorii lipsă → S8 inaccesibil. Erori: eroare server la salvare → mesaj cu buton „Reîncercați"; date locale ale sesiunii păstrate. 
• Formular de tipar al cererii — comportament normal: poate fi prezentat ca preview cu toate datele înregistrate; conținut specific per serviciu și postproces; Constrângeri: conținut read-only; reflectă starea datelor la momentul vizualizării. Devieri: generare eșuată → mesaj „Nu s-a putut genera formularul" + buton „Reîncercați". Erori: API indisponibil → eroare + reîncercare; datele cererii rămân intacte. 
• Butonul MSign — vizibilitate și inițiere — comportament normal: vizibil în viewport fără scroll (sticky sau în header/footer fix); la clic se inițiază fluxul MSign; după semnare cu succes, continuarea este activată. Constrângeri: poziție sticky obligatorie. Devieri: tentativă de continuare fără semnare → mesaj „Nu puteți continua fără a semna cererea"; butonul Continuare dezactivat. Erori: sesiune MSign eșuată → notificare + posibilitate reîncercare; cererea rămâne în starea curentă. 
• Mesaj schiță — comportament normal: mesajul „Schița salvată dar nefinisată va fi ștearsă automat în decursul <Timp setat>" afișat persistent; <Timp setat> configurat în GEAP BackOffice. Constrângeri: mesajul nu poate fi închis de utilizator. Devieri: timp neconfigurat → placeholder generic fără valoare concretă. Erori: nu se aplică (mesaj static). 
• Mesaj îndrumare - „Pentru corecții, navigați la pasul corespunzător din bara de progres." 
 Constraints: 
 • Ecranul de verificare este read-only editarea directa nu este permisa, doar navigarea la pasul corespunzator. 
• Formatul de tipar poate diferi vizual de PDF-ul final generat prin MDocs (diferente minore de rendering). 
• Câmpurile persoanei juridice (IDNO, Denumire companie, Telefon, Email companie) sunt afișate condiționat 
• Secțiunea Documente suplimentare este afișată condiționat — doar dacă au fost atașate documente suplimentare 
• Tipul solicitării este determinat de locul de inițiere: Servicii disponibile = procesare primară; Acte permisive = postproces cu tip precompletat 
• Date generale, Date despre solicitant și Atașamente sunt generice; Formularul cererii este specific per serviciu/postproces 
• Semnătura electronică MSign este obligatorie; continuarea fără semnare este blocată tehnic 
• Activitățile CAEM sunt afișate sortate A-Z; ordinea nu poate fi schimbată de utilizator 
 Risks: 
 • Pierderea datelor la navigarea inapoi daca starea formularului nu este persistata corect in sesiune/schita. 
• Discrepanta intre sumarul de verificare si PDF-ul final generat poate confuza utilizatorul. 
• Ecranul de verificare poate fi lung pentru serviciile cu multe campuri - necesita scroll si posibil sectiuni colapsabile. 
• API GEAP BackOffice — generarea Numărului dosarului și configurarea timpului de ștergere schiță 
• MSign (msign.gov.md) — semnătura electronică obligatorie; indisponibilitatea blochează fluxul 
• RSSPA — lista documentelor predefinite per serviciu 
• API generare formular de tipar — specific per serviciu; indisponibilitatea blochează preview-ul 
• Logica Tipului solicitării depinde de contextul de inițiere a dosarului (Servicii disponibile vs. Acte permisive)
